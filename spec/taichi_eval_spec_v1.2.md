# 太極拳姿勢評価プログラム 仕様書（v1.2 ドラフト）

制定套路の指導現場で、演者のキーポーズ写真を解析し、要訣に基づいたフィードバックを返す評価プログラムの仕様。v1.1 からの主な改訂は、**経時評価（改善判定）を単回評価と並ぶ第一級の機能に昇格**させ、それを支えるデータ保全の原則を定めたこと。

---

## 1. 目的

制定套路（24式等）の主要な定式（キーポーズ）について、演者の姿勢を要訣単位で評価し、指導の言葉に翻訳されたフィードバックとして提示する。

評価は2層からなる:

- **単回評価**: その日のそのポーズが要訣を満たしているか（スナップショット）
- **経時評価**: セッションを重ねる中で改善しているか（トレンド）。**指導の最終的な関心はこちらにあり、本プログラムの主目的とする。**

## 2. 想定ユーザー・前提条件

| 項目 | 内容 |
|------|------|
| ユーザー | 指導者（個別指導の材料、上達の経過観察）、演者本人（自己点検） |
| 対象套路 | 制定套路（24式等）。規定演技のため型の基準値が一意に定まる。 |
| 対象学習者 | **预备式が概ね成立している学習者**。预备式は全評価の基準点であり、これが大きく崩れる段階は対象外。 |
| 利用環境 | 教室または自宅。Mac 1台＋スマホ/デジカメで完結。写真・データはローカル処理（クラウド送信なし）。 |

## 3. 計測モデル — 4つの評価タイプ

| タイプ | 基準 | 評価の意味 | 必要な事前データ |
|--------|------|------------|------------------|
| **A 構造基準** | 幾何学（鉛直線・足の位置等） | 人によらず絶対評価 | なし |
| **B お手本基準** | 制定套路の規定＋先生のお手本 | 型の形の一致度 | お手本写真（複数枚→許容範囲） |
| **C 保持型** | 本人の预备式（＋怒らせ肩） | 基準姿勢を**どれだけ保てたか** | セッション毎キャリブレーション |
| **D 変化型** | 本人の预备式 | 習慣的緊張から**どれだけ緩める方向に動けたか** | セッション毎キャリブレーション |

### 3.1 セッション毎キャリブレーション

C・D の基準となる本人ベースラインは日々揺れるため、**セッション開始時に毎回撮影**する。

- 撮影内容: **预备式（正面・側面・背面）＋わざと肩を怒らせた立位（正面）** の計4枚
- 预备式の役割: C の「保持すべき理想状態」、D の「習慣的緊張を含む出発点」を兼ねる。
- 怒らせ肩の役割: 沈肩の **2点キャリブレーション**（预备式=すくみ率0%、怒らせ=100%）の上端。预备式との画像上の差が小さすぎる場合は「この撮影条件では沈肩を測れない」とする**感度チェック**を兼ねる。
- 品質ゲート: 预备式が構造基準を大きく外れる場合「ベースライン不適格」と警告し、C・D 評価を保留する。
- **ベースライン値自体を経時評価の対象として記録する（§5 参照）。**

### 3.2 評価タイプごとの単回判定

- **A**: 固定閾値（運用調整パラメータ、バージョン管理する）と比較。
- **B**: 制定套路の規定値を一次基準、先生のお手本複数枚（推奨5枚以上）の平均±2σ を許容範囲。範囲内=OK、±2σ超=注意、±4σ超=要修正。
- **C**: キャリブレーション軸上の比率（例: すくみ率15%）。閾値は比率に対して設定。
- **D**: 预备式からの変化量と方向。緩める方向を肯定的に、変化なし・逆方向を指摘対象とする。変化量の大きさの良否（緩めすぎ）は判定せず経過観察値とする。

## 4. 要訣の翻訳表

実現性: ◎=ランドマークで素直に測れる ○=工夫すれば可 △=シルエット解析頼みで要予備実験

### A 構造基準

| 要訣 | 指標 | 評価面 | 実現性 |
|------|------|--------|--------|
| 立身中正 | 体幹軸（肩中点–尻中点）の鉛直からの傾き角 | 正面＋側面 | ◎ |
| 膝不過足尖（弓歩前膝） | 膝が足首鉛直線より前に出ているか | 側面 | ◎ |
| 膝とつま先の向き | 膝の内倒れ（足首–尻線からの内側偏位） | 正面 | ○ |
| 墜肘 | 肘向きの鉛直からの外向き角（§4.1） | ポーズごとに指定 | ◎ |

#### 4.1 墜肘の測定方法

肘の向きは **肘→肩ベクトルと肘→手首ベクトルの角二等分線の逆方向**（肘頭の向き）として復元し、鉛直下向きとの成す角を、正中線から離れる側を正として算出する。

- 閾値（仮置き・調整パラメータ）: 〜45度=OK / 45〜70度=注意 / 70度〜=要修正
- **肘角度160度超（腕がほぼ伸びている）は原理的に測定不能**と表示。
- 評価面はポーズ依存（キーポーズ定義に含める）。擬似3D角度は参考値として併記可。

### B お手本基準

| 要訣 | 指標 | 評価面 | 実現性 |
|------|------|--------|--------|
| 弓歩の後脚（蹬脚） | 後膝の角度 | 側面 | ◎ |
| 屈膝鬆跨（馬歩等の沈み） | 両膝角度＋尻の相対高さ | 正面 | ◎ |
| 虚実分明（重心配分） | 尻中点の両足首間に対する水平位置比 | 側面 | ◎ |
| 歩幅・架式の高さ | 足首間距離／体幹長、尻の高さ | 正面・側面 | ◎ |

### C 保持型

| 要訣 | 指標 | 評価面 | 実現性 |
|------|------|--------|--------|
| 沈肩 | 肩–耳間距離のすくみ率（预备式0% ↔ 怒らせ100%） | 正面 | ◎ |
| 虚領頂勁 | 耳–肩の鉛直整列（頭部前方偏位）の预备式比での保持 | 側面 | ○ |

### D 変化型

| 要訣 | 指標 | 評価面 | 実現性 |
|------|------|--------|--------|
| 骨盤の立ち（斂臀・尾閭中正） | シルエット腰部くぼみ深さの预备式からの減少量 | 側面 | △ |
| 含胸 | 肩の前方位置／胸部シルエットの変化 | 側面 | △ |
| 抜背（肩甲骨の開き） | 上背部シルエットの幅・丸みの変化 | 背面 | △ |

※ D はセグメンテーションマスク解析に依存。**評価用撮影は体に沿った服（Tシャツ等）**を必須とする。Phase 1.5 で予備実験、判別不能なら SMPL 系メッシュ復元へ移行判断（§12）。

### 対象外の要訣

呼吸・意識・勁の通りなど外形に現れないもの。本プログラムは指導者の眼を置き換えない。

## 5. 経時評価（改善判定）

本プログラムの主目的。演者 × キーポーズ × 要訣 ごとの時系列に対して行う。

### 5.1 データ保全の原則

経時評価の信頼性は、データの取り方で決まる。以下を原則とする。

1. **一次データは生の測定値**（角度・比率・座標）。判定（OK/注意/要修正）は閾値から導出される二次データであり、保存はするが、**閾値セットのバージョンを付与し、いつでも再計算可能**とする。閾値を調整しても過去との比較可能性を失わない。
2. **元写真を保存する**。姿勢推定モデルの更新時に全履歴を再抽出し、新旧の測定値系列を並存できるようにする（レコードに抽出エンジンのバージョンを付与）。改善トレンドの再解析が将来にわたり可能であること。
3. **追記専用**。測定レコードは追記のみとし、上書き・削除しない。誤記の訂正は打ち消しレコードで行う。

### 5.2 測定レコード形式

1測定 = 1レコードの JSONL（`measurements.jsonl`）。フラットで `awk` / `jq` による集計が容易な形式とする。CSV 書き出しを併設。

主要フィールド:

| フィールド | 内容 |
|------------|------|
| `schema_version` | レコード形式のバージョン |
| `timestamp` / `session_id` | 測定日時・セッション識別子 |
| `performer_id` | 演者（表示名は別管理） |
| `pose_id` / `direction` | キーポーズと撮影方向。ベースライン写真は `pose_id="baseline"` |
| `metric_id` | 指標の識別子（例: `elbow_flare_deg_r`, `shrug_ratio_r`, `trunk_tilt_deg`） |
| `eval_type` | A / B / C / D |
| `value_raw` | 生の測定値 |
| `confidence` | 信頼度。測定不能時はレコード自体に `unmeasurable` フラグと理由 |
| `judgment` | 導出判定（OK/注意/要修正） |
| `threshold_set_version` | 判定に使った閾値セットのバージョン |
| `extractor_version` | 姿勢抽出エンジンのバージョン |
| `image_ref` | 元写真への相対パス |

### 5.3 改善判定の方法

- **ノイズ床の実測**: 同一人物・同一ポーズ・同条件の連続2回撮影のばらつき（§11 受け入れ基準で取得）を、指標ごとの**測定ノイズ床**として記録する。
- **トレンド3区分**: 直近 N セッション（既定 N=5）の移動平均の変化が、ノイズ床を上回って改善方向なら「改善」、悪化方向なら「後退」、それ未満は「横ばい」。**1回の良い値で「上達」とは言わない。**
- **判定遷移の併記**: 要修正→注意→OK の遷移履歴を離散的なマイルストーンとして表示する（本人のモチベーション用途）。
- **ベースライン系列の追跡（D系の改善の正しい現れ方）**: D 系の癖が本当に改善すると、预备式自体が改善し「预备式からの変化量」はむしろ**減少**する。したがって D 系の経時評価は、(a) セッション毎ベースライン値の系列を主、(b) 変化量の系列を従として判定する。変化量の減少をベースライン改善と併せて読み、「緩める必要が減った」を正しく改善と判定する。
- **C 系の補助系列**: すくみ率に加え、キャリブレーション幅（预备式↔怒らせ肩の差）も記録する。幅の経時的な縮小は撮影条件の劣化または可動の変化を示すシグナルとして扱う。

### 5.4 経時レポート

- 演者 × 要訣の推移グラフ（生値＋移動平均＋ノイズ床帯）。
- セッションサマリ: 前回比・直近Nセッション比のトレンド3区分を要訣ごとに一覧。
- 期間レポート（例: 3ヶ月）: 改善した要訣・横ばいの要訣・後退した要訣を指導の言葉で要約。Markdown / CSV 書き出し（Obsidian・表計算での管理を想定）。

## 6. 機能要件

### F1. 撮影ガイド
撮影条件チェックリスト（カメラ高さ・距離・方向・背景・**服装**）。撮影メタ情報（方向・キーポーズ・演者・日付・セッションID）の記録。

### F2. セッションキャリブレーション
预备式3面＋怒らせ肩1枚の登録、ベースライン算出、感度チェック、品質ゲート。**ベースライン値の測定レコード化（経時追跡対象）。**

### F3. 姿勢抽出
ランドマーク＋セグメンテーションマスク＋信頼度の抽出。複数人時は中央・最大の人物を選択し注釈画像で確認可能。

### F4. お手本登録（B基準用）
キーポーズ×方向ごとの複数枚登録と許容範囲算出・再計算。

### F5. 単回評価
A〜D の各方法で要訣ごとに OK/注意/要修正/測定不能/未評価 を判定。左右は演者本人基準。重み付き総合スコア（経過観察用と明記）。墜肘(A)と沈肩(C)の相関セルフチェック併記。

### F6. フィードバック表示
指導の言葉での判定表示（付録A）、正規化骨格の重ね描き比較図、Markdown/CSV書き出し。

### F7. 測定データ保管
§5.1〜5.2 に従う JSONL への追記保存、元写真の保管、閾値セット・抽出エンジンのバージョン管理、CSV書き出し。

### F8. 経時評価
§5.3〜5.4 に従うトレンド判定と経時レポート。モデル更新時の全履歴再抽出（バッチ）機能。

## 7. 非機能要件

| 項目 | 要件 |
|------|------|
| 動作環境 | Mac（Apple Silicon）、Python 3.12系。ネット接続は初回モデル取得時のみ。 |
| 処理時間 | 単回評価は1枚あたり数秒以内。経時レポートはセッション後のバッチで可。 |
| プライバシー | 写真・データはローカル保存。演者名は表示名（ニックネーム可）で `performer_id` と分離管理。 |
| 操作性 | 第一段階はCLI。セッションの流れ（キャリブレーション→各演者撮影→サマリ）を最小タイプ数で。 |
| データ互換 | 全保存データに schema_version。測定データはフラットファイル（JSONL/CSV）でロックインなし。Phase 1 ではDBを持たない。 |

## 8. データ設計（論理）

```
data/
├── keyposes/                      # キーポーズ定義（要訣・重み・評価面）
│   └── <pose_id>.json
├── thresholds/                    # 閾値セット（バージョン管理）
│   └── <version>.json
├── references/                    # お手本（B基準）
│   └── <pose_id>/<direction>/     #   写真群と許容範囲(stats.json)
├── performers/
│   └── <performer_id>/
│       ├── profile.json           #   表示名等
│       └── sessions/<date>/
│           ├── baseline/          #   预备式3面＋怒らせ肩（元写真＋抽出結果）
│           └── <pose_id>/         #   評価写真（元写真＋抽出結果）
├── measurements.jsonl             # 全測定レコード（追記専用・awk/jq可読）
└── reports/                       # 書き出しレポート(md/csv)
```

## 9. エラー・例外時の挙動

| 状況 | 挙動 |
|------|------|
| 人物を検出できない | 「検出失敗」を明示。評価値は出さない。 |
| 指標の信頼度が低い | 「測定不能」とし総合スコアの分母から除外。レコードには理由付きで記録。 |
| 必要な評価面の写真がない | 「未評価」。代替値での推定はしない。 |
| 肘角>160度 | 墜肘「測定不能（原理的制約）」。 |
| キャリブレーション感度不足 | 当該セッションの沈肩「測定不能（感度不足）」、撮影条件の改善を提案。 |
| 预备式が品質ゲート不合格 | 警告の上 C・D を保留。A・B のみ評価。 |
| お手本枚数不足（<3枚） | 信頼性低下を警告した上で暫定評価。 |
| 経時データのセッション数不足（<N） | トレンド判定を保留し「データ蓄積中」と表示。 |

**誤った数値を黙って出すことを最も避ける。不明なものは不明と表示する。経時判定はノイズ床を超えるまで「横ばい」と言い切る。**

## 10. 制約・免責

- 単眼2D推定が基礎。回旋は直接測定できない。
- D 系はシルエット解析の予備実験結果次第（§12 Phase 1.5）。
- 評価値は同一撮影条件下の相対比較にのみ意味を持つ。撮影条件の変更は経時系列の断絶として記録する。
- 医学的・競技採点的な正確性は保証しない。指導者の眼の補助具である。

## 11. 受け入れ基準

### 単回評価（Phase 1）
- 同条件2回撮影で要訣判定が一致し、**そのばらつきがノイズ床として記録される**。
- 体幹を10度傾けた写真で「立身中正: 要修正」が方向付きで検出される。
- 肘を水平近くまでめくった写真で「墜肘: 要修正」、下に向けた写真で「OK」、伸ばした腕で「測定不能」。
- 预备式・怒らせ肩からすくみ率0%/100%が較正され、中間のすくみが中間値として出る。
- 側面写真なしで側面系要訣が「未評価」。検出失敗時に評価値が出ない。

### データ・経時評価（Phase 2）
- 閾値セットを変更しても、過去の生値から新閾値での判定が再計算できる。
- 抽出エンジンを差し替えて全履歴を再抽出でき、新旧系列が区別して保持される。
- ノイズ床未満の変動が「横ばい」と判定され、超える系統的変化のみ「改善/後退」と判定される。
- D 系で、ベースライン改善に伴う変化量減少が「改善」として正しく報告される。

## 12. 段階的開発計画
