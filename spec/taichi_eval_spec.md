# 太極拳姿勢評価プログラム 仕様書（v1.0 ドラフト）

太極拳の指導現場で、演者のキーポーズ写真をお手本と比較し、要訣に基づいた具体的なフィードバックを返す評価プログラムの仕様。実装プロトタイプ（pose_angles.py / pose_compare.py）とは独立に、目的側から要件を定義する。

---

## 1. 目的

太極拳の套路における主要な定式（キーポーズ）について、演者の姿勢がお手本からどの要訣でどれだけ外れているかを定量化し、**指導の言葉に翻訳されたフィードバック**として提示する。

数値の羅列ではなく、「体幹が前に倒れている」「弓歩の膝がつま先より出ている」といった、指導者が普段使う表現で結果を返すことを最重要の設計方針とする。

## 2. 想定ユーザーとユースケース

| ユーザー | ユースケース |
|----------|--------------|
| 指導者 | 教室で各演者のキーポーズを撮影し、お手本との差を確認して個別指導の材料にする。回を重ねた変化（上達）を追う。 |
| 演者本人 | 自分の写真をお手本と比べ、自己点検する。指導の復習に使う。 |

利用環境は教室または自宅。Mac 1台＋スマホ/デジカメで完結し、クラウド送信を必須としない（個人の写真を扱うため、ローカル処理を原則とする）。

## 3. 評価の基本方針

### 3.1 要訣ベースの評価

太極拳の指導で用いられる要訣を、姿勢推定で測定可能な指標に翻訳する。評価・表示の単位は関節角度ではなく**要訣**とする。

| 要訣 | 意味 | 測定指標（単眼2Dで可能なもの） | 評価面 |
|------|------|-------------------------------|--------|
| 立身中正 | 体幹をまっすぐ立てる | 体幹軸（肩中点–尻中点）の鉛直からの傾き角 | 正面・側面 |
| 沈肩 | 肩を沈める | 両肩線の水平からの傾き、肩–耳間の距離比（すくみ検出） | 正面 |
| 墜肘 | 肘を落とす | 肘の高さ（肩に対する相対位置）、肘角度 | 正面・側面 |
| 弓歩の前膝 | 膝がつま先を越えない | 側面での膝–足首の水平位置関係、前膝の角度 | 側面 |
| 弓歩の後脚 | 後脚を伸ばし蹬脚する | 後膝の角度 | 側面 |
| 馬歩の沈み | 跨を沈める | 両膝の角度、尻の高さ（膝に対する相対位置） | 正面 |
| 重心の位置 | 前後の重心配分 | 尻中点の、両足首間に対する水平位置の比 | 側面 |
| 頭頂の懸（虚領頂勁） | 頭をまっすぐ吊る | 耳–肩の鉛直整列（頭部前方偏位） | 側面 |

注: 含胸抜背・気沈丹田など、外形に現れにくい要訣は本プログラムの対象外とする（§9 制約）。

### 3.2 正面・側面の2面評価

単眼カメラの奥行き喪失を補うため、**正面（前額面）と側面（矢状面）の2方向から撮影**し、要訣ごとに評価に適した面を使う（上表「評価面」列）。側面写真がない場合、側面系の要訣は「未評価」と明示する（誤った値を出さない）。

### 3.3 キーポーズ単位の評価

套路全体ではなく、静止が成立する**定式（キーポーズ）**を評価単位とする。例: 起勢、摟膝拗歩の定式、単鞭、雲手の極点、十字手。評価対象とするキーポーズは指導者が登録し、それぞれにお手本データを持つ。

### 3.4 お手本の許容範囲

お手本は1枚ではなく、**同一キーポーズの複数枚（推奨5枚以上）**から指標ごとの平均と標準偏差を算出し、許容範囲（平均±2σ を既定）を持つ。演者の値が範囲内なら合格、外れた項目のみ指摘する。これにより:

- お手本自身の自然なばらつきを誤差として吸収する
- 「すべての項目で差が出る」数値羅列を避け、指摘を本当に外れた項目に絞る

### 3.5 重み付け

要訣には指導上の重要度の差がある。キーポーズごとに要訣の重み（高・中・低の3段階）を指導者が設定でき、総合評価はこの重みを反映する。既定値は立身中正・弓歩の前膝・重心位置を「高」とする。

## 4. 機能要件

### F1. 撮影ガイド

- 撮影条件を統一するためのチェックリストを提示する: カメラ高さ（腰の高さ推奨）、距離（全身＋足元の余白）、方向（正面/側面）、背景（無地推奨）。
- 撮影条件のメタ情報（方向・キーポーズ名・演者名・日付）を画像と紐づけて記録する。

### F2. 姿勢抽出

- 静止画1枚から人物1名の骨格ランドマークを抽出する。
- 複数人が写っている場合は画像中央・最大の人物を選択し、選択結果を注釈画像で確認できること（誤検出の発見手段）。
- 各指標に信頼度を付与し、信頼度の低い指標は評価から除外して「測定不能」と表示する。

### F3. お手本登録

- キーポーズ × 撮影方向ごとに、お手本写真を複数枚登録できる。
- 登録時に指標ごとの平均・標準偏差・許容範囲を算出して保存する。
- お手本の追加・差し替えに伴う許容範囲の再計算ができる。

### F4. 評価

- 演者写真1枚を指定キーポーズのお手本と比較し、要訣ごとに3段階で判定する:
  - **OK**（許容範囲内）/ **注意**（範囲外、軽度）/ **要修正**（範囲外、重度。閾値は±2σ超と±4σ超を既定）
- 判定には方向を含む（例: 体幹が「前」に倒れている／膝が「内」に入っている）。方向は演者本人の左右で表現し、画像上の左右と取り違えない。
- 重み付き総合スコア（100点満点）を算出する。スコアは経過観察用であり、絶対評価ではない旨を表示に明記する。

### F5. フィードバック表示

- 要訣ごとの判定を、指導の言葉で表示する。例:
  - 「立身中正: 要修正 — 体幹が前に約8度倒れています（お手本範囲: ±3度）」
  - 「弓歩の前膝: OK」
- 比較図を出力する: お手本（許容範囲の帯付き）と演者の骨格を正規化して重ね描きし、要修正の部位を強調表示する。
- 結果は画面表示のほか、Markdown / CSV で書き出せる（Obsidian・表計算での管理を想定）。

### F6. 履歴管理

- 演者 × キーポーズごとに評価履歴を保存し、指標の推移（上達）を時系列グラフで表示できる。
- データはローカルのディレクトリ構造＋JSONで保持し、特定アプリにロックインしない。

## 5. 非機能要件

| 項目 | 要件 |
|------|------|
| 動作環境 | Mac（Apple Silicon）、Python 3.12系。インターネット接続は初回のモデル取得時のみ。 |
| 処理時間 | 1枚あたり数秒以内（教室でその場で見せられる速度）。 |
| プライバシー | 写真・評価データはすべてローカル保存。クラウド送信なし。演者名は表示名（ニックネーム可）で管理。 |
| 操作性 | 第一段階はCLI（シェルから一括処理可能）。将来的に簡易GUIまたはWebローカルUIを検討。 |
| データ互換 | すべての保存JSONに schema_version を持たせ、形式変更時の移行手段を提供する。 |

## 6. データ設計（論理）

```
data/
├── keyposes/                  # キーポーズ定義
│   └── <pose_id>.json         #   名前、評価する要訣と重み、必要な撮影方向
├── references/                # お手本
│   └── <pose_id>/<direction>/ #   写真群と算出済み許容範囲(stats.json)
├── performers/                # 演者
│   └── <performer_id>/
│       └── <pose_id>/         #   日付別の写真・抽出結果・評価結果
└── reports/                   # 書き出したレポート(md/csv)
```

主要JSONはいずれも `schema_version`、元画像への相対パス、撮影メタ（方向・日付）を必須キーとする。

## 7. 評価処理フロー

添付 `taichi_eval_flow.drawio` 参照（VSCode の draw.io 拡張で表示）。概略:

1. 指導者がキーポーズを定義し、お手本写真を登録 → 許容範囲を算出
2. 演者のキーポーズ写真を撮影（正面・側面）
3. 姿勢抽出 → 要訣指標の算出（信頼度付き）
4. お手本の許容範囲と照合 → 要訣ごとに OK/注意/要修正 を判定
5. 指導の言葉によるフィードバック＋比較図＋履歴更新

## 8. エラー・例外時の挙動

| 状況 | 挙動 |
|------|------|
| 人物を検出できない | 「検出失敗」を明示し、撮影ガイドの再確認を促す。評価値は出さない。 |
| 指標の信頼度が低い（隠れ・ブレ） | 当該要訣を「測定不能」とし、総合スコアの分母から除外する。 |
| 必要な撮影方向の写真がない | 当該要訣を「未評価」と表示する。代替値での推定はしない。 |
| お手本枚数が不足（<3枚） | 許容範囲の信頼性が低い旨を警告した上で暫定評価する。 |

誤った数値を黙って出すことを最も避ける。不明なものは不明と表示する。

## 9. 制約・免責

- 単眼2D推定が基礎であり、各面の評価はその面に投影された形に対するもの。体の回旋そのものは直接測定できない。
- 外形に現れない要訣（呼吸、意識、勁の通り）は対象外。本プログラムは外形チェックの補助具であり、指導者の眼を置き換えるものではない。
- 評価値は同一撮影条件下での相対比較にのみ意味を持つ。撮影条件が変われば数値の連続性は保証されない。
- 医学的・競技採点的な正確性は保証しない。

## 10. 段階的開発計画

| フェーズ | 内容 | 既存プロトタイプとの関係 |
|----------|------|--------------------------|
| Phase 1 | 正面・側面の静止画によるキーポーズ評価（本仕様の F1〜F5） | pose_angles.py / pose_compare.py を要訣ベースに再構成して流用 |
| Phase 2 | 履歴管理と推移グラフ（F6）、簡易UI | 新規 |
| Phase 3 | 動画からのキーポーズ自動切り出し（定式で静止した瞬間の検出） | 新規 |
| Phase 4 | 複数カメラによる3D化（回旋・奥行きの直接測定。Pose2Sim 等の活用） | 検討 |

## 11. 受け入れ基準（Phase 1）

- 同一人物・同一ポーズを同条件で2回撮影したとき、要訣判定（OK/注意/要修正）が一致すること（再現性）。
- 意図的に体幹を10度傾けた写真で「立身中正: 要修正」が方向付きで検出されること。
- 側面写真なしの評価で、側面系要訣が「未評価」と表示されること。
- 検出失敗時に評価値が一切出力されないこと。

## 付録A: 要訣判定の表現例

| 判定 | 表示例 |
|------|--------|
| OK | 立身中正: OK（傾き1.2度 / 許容±3度） |
| 注意 | 沈肩: 注意 — 右肩がやや上がっています（差+4度） |
| 要修正 | 弓歩の前膝: 要修正 — 膝がつま先より前に出ています |
| 測定不能 | 墜肘: 測定不能（左肘が体に隠れています） |
| 未評価 | 重心位置: 未評価（側面写真が必要です） |
